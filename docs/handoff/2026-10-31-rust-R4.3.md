# R4.3 — `hs-streamlabs-setup` (ตัวติดตั้ง Streamlabs เป็น Rust)

วันที่ 31 ตุลาคม 2026 · branch `rs/R4.3-streamlabs-setup` (แตกจาก `1102380`) · commit ใน branch เท่านั้น ไม่ push · ยังไม่ผ่านรีวิว Opus ตาม PLAN 10.4 (ตารางสถานะ 0.4 ไม่ได้แก้)

## สถานะ

port ครบ `obs/streamlabs-setup/main.cpp` (281 บรรทัด) เป็น crate `rust/crates/hs-streamlabs-setup` ได้ exe ชื่อ `hearaside-streamlabs.exe` (ชื่อ bin ตั้งตามสัญญากับตัวติดตั้ง ไม่ใช่ชื่อ crate) พิสูจน์ด้วยการรัน C++ exe จริงกับ Rust บนโฟลเดอร์ Streamlabs ปลอมชุดเดียวกันทีละคำสั่ง: exit code, stdout, stderr, และทุกไบต์ของไฟล์ที่เขียน (app.asar, สำรอง, plug-in, marker, state) ตรงกันหมด

## สัญญาที่ตัวติดตั้งใช้ (คงไว้ทุกข้อ)

ที่มา: `installer/windows/hearaside.iss` (บรรทัด 185–282) และ `build-installer.ps1` (บรรทัด 58–80)

1. ชื่อ exe `hearaside-streamlabs.exe` ติดตั้งที่ `{app}\streamlabs\` ข้างๆ `hearaside-obs.dll` และ extract ไป `{tmp}` ตอนเริ่ม wizard เพื่อเช็กเวอร์ชันที่ลงอยู่
2. CLI: `check <โฟลเดอร์>` (ตัวติดตั้งเรียกตอนเปิด wizard และก่อนกด Next), `install <โฟลเดอร์> <hearaside-obs.dll>` (ssPostInstall), `repair <โฟลเดอร์> <dll>` (scheduled task `\HEARASIDE\Streamlabs repair` รันตอนบูตและทุก 15 นาที ในนาม SYSTEM), `uninstall <โฟลเดอร์>`. โฟลเดอร์ = `{commonpf64}\Streamlabs OBS`
3. exit code: 0 สำเร็จ, 1 ใช้ผิด, 2 Streamlabs รันอยู่ (กับ `check` = "ติดตั้งได้แต่รันอยู่"), 3 เวอร์ชัน Streamlabs ไม่รองรับ, 4 ไม่พบ, 5 ล้มเหลว. ตัวติดตั้งอ่าน 0/2 = ใช้ได้, 3 = libobs อื่น, 4 = ไม่ได้ลง
4. ข้อความ error ขึ้น stderr (ตัวติดตั้งแสดงเฉพาะรหัส) ข้อความสำเร็จขึ้น stdout: `HEARASIDE source installed in Streamlabs Desktop` / `Streamlabs Desktop restored` ข้อความเหมือน C++ ทุกตัวอักษร
5. ไฟล์ที่เขียน/ลบ (ใน `<โฟลเดอร์>`): `resources\app.asar` (แพตช์ bundle `renderer.*.js` 7 จุด + อัปเดต size/offset/integrity ใน header), `resources\app.asar.before-hearaside` (ต้นฉบับ), `resources\app.asar.hearaside-tmp` (ชั่วคราว ลบเมื่อล้ม), `resources\app.asar.hearaside-state` (`"<ขนาด> <mtime ms>"`), `force-local-bundles` (ไฟล์ว่าง), และ `resources\app.asar.unpacked\node_modules\obs-studio-node\obs-plugins\64bit\hearaside-obs.dll`. ไม่เขียน registry, ไม่แตะ appdata
6. ลำดับตรวจเดิม: ไม่พบ app.asar/obs.dll → 4 (ก่อนตรวจคำสั่ง ก่อนตรวจว่ารันอยู่); `uninstall` ตรวจว่ารันอยู่ก่อนเสมอ; `install`/`repair` ไม่มี dll → "unknown command" 1; `repair` ที่ติดตั้งแล้ว (state ตรง, marker มี, plug-in ตรงไบต์กับ dll) → 0 โดยไม่แตะไฟล์
7. **ไม่ได้แก้ installer script** ชื่อ exe ไม่เปลี่ยน. สิ่งที่ต้องทำตอน R9 (ไม่ใช่ตอนนี้): `build-installer.ps1` บรรทัด 60 ชี้ `$slobsTool` ไปที่ `build\obs\streamlabs-setup\hearaside-streamlabs_artefacts\Release\hearaside-streamlabs.exe` (CMake) ต้องเปลี่ยนเป็น `rust\target\release\hearaside-streamlabs.exe` ตอนเลิกใช้ C++ (`rust/.cargo/config.toml` ตั้ง `crt-static` ไว้แล้ว จึงไม่พึ่ง VC++ runtime บนเครื่องผู้ใช้)

## ไฟล์

## บั๊ก C++ ที่แก้ / ที่ต่างโดยไม่เปลี่ยนสัญญา

1. **อาร์กิวเมนต์ที่ไม่ใช่ ASCII**: C++ ใช้ `main(int, char**)` (ANSI code page บน Windows) แล้วตีความเป็น UTF-8 ถ้าผู้ใช้เลือกโฟลเดอร์ติดตั้ง HEARASIDE ที่มีตัวอักษรไทย พาธ dll ที่ส่งมา (ผ่าน `{app}`) น่าจะเพี้ยนและ `install`/`repair` ล้ม (4) (วิเคราะห์จากโค้ด ไม่ได้ลองรัน). Rust อ่านแบบ wide (`args_os`) จึงใช้ได้. ไม่ได้ทดสอบกับพาธไทยจริง (ไม่มี test พาธไทยในชุดไหนเลย)
2. **bundle ผ่าน `juce::String`**: C++ แปลง bundle เป็น `String` แล้วกลับเป็น UTF-8 ถ้ามีไบต์ที่ไม่ใช่ UTF-8 ที่ถูกต้องจะถูกเปลี่ยน; Rust ค้น/แทนที่ที่ระดับไบต์ (bundle จริงเป็น UTF-8 ล้วน ผลจึงเหมือนกัน)
3. `sameFile` ใน C++ ถ้าเปิด dll ไม่ได้ จะเทียบแฮชของ stream ว่าง (ขนาดไฟล์ 0 ทั้งคู่ก็ถือว่าเหมือน); Rust ถือว่า "ไม่เหมือน" เมื่ออ่านไม่ได้ (ต่างกันเฉพาะ plug-in ขนาด 0 ที่ติดตั้งไว้ + dll หาย ซึ่ง `install` จะได้ 4 อยู่ดี)
4. stdout ของ C++ ผ่าน text mode ของ Windows จึงลงท้าย `\r\n`; Rust เขียน `\n` (ตัวติดตั้งไม่อ่าน stdout ของมัน; ชุดเทียบ C++ ปรับ `\r\n` เป็น `\n` ก่อนเทียบ)
5. `replaceWithText` ของ state ใน C++ เขียนผ่านไฟล์ชั่วคราวแล้วแทนที่; Rust เขียนตรง (`fs::write`) ถ้าดับกลางทางจะได้ state ผิด ซึ่งแค่ทำให้ `repair` รอบถัดไปติดตั้งซ้ำ (ไม่เสียหาย)
6. JSON: ตัวเลขทศนิยมใน header พิมพ์ด้วยกฎประมาณ (ลงตัวแสดง `.0`, ไม่ใช่ `serialiseDouble` เต็มของ JUCE) เพราะ header ของ asar ไม่มีทศนิยมจริง (size เป็นจำนวนเต็ม, offset เป็นสตริง). ในชุดเทียบ C++ ใส่ `1.5`/`2.0e3` ใน header แล้วตรงกัน; ไม่รองรับ header ที่เป็น UTF-16 (JUCE ตรวจ BOM) รองรับ UTF-8 BOM

## ที่ข้าม / ยังไม่ได้ตรวจ

1. **ยังไม่ได้ลง Streamlabs Desktop จริง**: ทดสอบกับโฟลเดอร์ปลอมที่สร้าง asar ตาม layout จริง (pickle + JSON + ข้อมูล) และ bundle ที่มี anchor ครบ ไม่ได้ลองกับ `app.asar` ของ Streamlabs เวอร์ชันจริง (ซึ่งใหญ่หลายร้อย MB และมี header ซับซ้อนกว่า) ไม่ได้ตรวจว่า Streamlabs เปิดขึ้นมาแล้วเห็นแหล่ง HEARASIDE. ควรให้ ArmZ รัน `hearaside-streamlabs.exe check "C:\Program Files\Streamlabs OBS"` ของทั้ง C++ และ Rust เทียบกันบนเครื่องที่ลง Streamlabs จริงก่อนปล่อย
2. การตรวจว่า Streamlabs รันอยู่ (`streamlabs_running`) เทียบ C++ จริงไม่ได้ในชุดเทียบ (ชุดเทียบข้ามเมื่อ `Streamlabs OBS.exe` กำลังรัน); โค้ด Toolhelp ทดสอบเฉพาะกรณี "ไม่รัน" บนเครื่องนี้ ส่วนกรณีรันอยู่ทดสอบผ่านการฉีด `running = true` เท่านั้น
3. **`unsafe` ใหม่ 1 บล็อก** (Toolhelp snapshot ใน `streamlabs_running`, มี `// SAFETY:`) PLAN หัวข้อ 8 ข้อ 5 ระบุ crate ที่มี `unsafe` ได้ไว้ ควรเพิ่ม `hs-streamlabs-setup` ในรายการนั้น (ไม่ได้แก้แผนตามคำสั่ง) ทางเลือกที่ไม่มี `unsafe` คือเรียก `tasklist` ซึ่งช้ากว่าและพึ่ง exe ภายนอก จึงไม่เลือก
4. `cargo deny check` เต็ม (รวม advisories) รันไม่ได้บนเครื่องนี้: cargo-deny 0.18.4 อ่าน advisory DB ไม่ได้ (RUSTSEC-2026-0146 ใช้ CVSS 4.0 ที่เวอร์ชันนี้ไม่รองรับ) ไม่เกี่ยวกับ crate นี้ ที่รันได้และผ่านคือ `licenses bans sources` (crate นี้ไม่เพิ่ม dependency ใหม่ใน lockfile)
5. ไม่ได้ build/ทดสอบบน Linux (โค้ดมี `#[cfg(not(windows))]` ให้ `streamlabs_running` = false เพื่อให้ workspace compile ได้; ชุดเทียบ C++ เป็น Windows เท่านั้น)
6. SHA-256 เขียนเองเพื่อไม่เพิ่ม dependency (ใช้เฉพาะ integrity ของ asar และเทียบไฟล์ plug-in ไม่ใช่เรื่องความปลอดภัย); ตรวจกับเวกเตอร์ NIST 4 ชุด (รวม 1,000,000 ตัวอักษร `a`) และเทียบผลกับ JUCE ผ่านชุดเทียบ C++ (hash ใน integrity ตรงทุกไบต์). ถ้ารีวิวอยากใช้ crate (`sha2`) แทน เปลี่ยนที่ `sha256.rs` ไฟล์เดียว
7. worktree นี้ไม่มี `external/*` จึงทำ junction ไป `Hearaside plugin\external\*` (JUCE, libdatachannel, mbedtls, obs-studio, opus, speexdsp) เพื่อ build `hs-net` / `hs-obs` ตอนรัน workspace (ไม่ได้ commit)
