# ตรวจเว็บ HEARASIDE ครั้งที่ 1

วันที่: 30 ตุลาคม 2026 (Asia/Bangkok)

โหมด: antislop after ตามที่ผู้ใช้เลือก รายงานนี้ยังไม่ได้แก้ source code และไม่ได้เผยแพร่เว็บ

ขอบเขต: `web/site` (React, Vite, Express) และ configuration ที่เกี่ยวข้อง ไม่เปลี่ยนปลั๊กอินหรือ Rust

ข้อกำหนดด้านภาพ: รักษาสีเทาอุ่น ฟอนต์ Anuphan ภาพปลั๊กอิน ปุ่มดำ โครงหน้า และลำดับเนื้อหาเดิม ปรับเฉพาะความผิดพลาด ความชัดเจน และการใช้งาน ไม่เสนอเปลี่ยนแบรนด์หรือออกแบบหน้าใหม่

## สิ่งที่ตรวจแล้ว

- `npm test`: ผ่าน 7 ไฟล์ รวม 53 tests
- `npm run build`: ผ่าน client, SSR และ prerender 20 หน้า มี warning ว่า initial JS chunk 609.87 kB (gzip 189.07 kB) เกิน budget 600 kB ไม่ถือว่า build ล้มเหลว
- `npm run typecheck`: ไม่ผ่านที่ `server/routes/share.ts:62` (TS2345)
- เปิดหน้าสาธารณะ/สถานะออกจากระบบ 16 URL ที่ 390px และ 1440px ทั้ง light/dark รวม 64 กรณี ไม่พบ JavaScript page error หรือภาพที่โหลดเสียในกรณีเหล่านี้
- ตรวจ axe ใน 40 กรณีของหน้าสาธารณะ และ 18 กรณีของหน้าหลังล็อกอิน บันทึกข้อผิดพลาดไว้ในหลักฐาน ไม่อ้างว่าเป็น accessibility certification
- ตรวจเพิ่มเติมที่ 320px, 768px และ 1024px สำหรับหน้าไทย หน้าสมัคร และหน้าดาวน์โหลด
- ทดสอบสมัครสมาชิก ล็อกอินภาษาไทย และบันทึกชื่ออัตโนมัติกับ API แบบ memory ในเครื่องเท่านั้น ไม่ใช้บัญชีหรือฐานข้อมูลจริง
- ทดสอบหน้า account ทั้ง 5 หมวดและหน้าเชื่อมปลั๊กอินที่ 320px, 390px และ 1440px
- ตรวจ mobile menu เปิด/ปิด, Escape และการคืน focus, เปลี่ยนภาษา, สถานะปุ่มธีม, submit ฟอร์มว่าง, อายุของ audio player และจำลอง API ตอบ 503
- เลื่อนผ่านเนื้อหา reveal ก่อนประเมิน screenshot/contrast ไม่ใช้ข้อความระหว่าง fade เป็นหลักฐานว่าโทนสีเดิมอ่านไม่ออก

หลักฐาน: [ผลสแกน](evidence/audit-001/results.json), [ทดสอบเส้นทางใช้งาน](evidence/audit-001/probes.json), [จำลองข้อผิดพลาด](evidence/audit-001/faults.json)

## รายการให้เลือกแก้

หมายเลขใช้สำหรับอนุมัติเป็นรายข้อ ระดับ antislop HIGH อิง Hard Gate ส่วน P1/P2/P3 แยกผลกระทบจริงเพื่อช่วยจัดลำดับ

### 1. P1 / HIGH: ตัวจำกัดคำขอ TURN ไม่ทำงาน

- กฎ: R-26, C-2 (พฤติกรรมที่มีอยู่ต้องทำงานจริง)
- ตำแหน่ง: `web/site/server/routes/share.ts:62`, `web/site/server/lib/limit.ts:44`
- สาเหตุ: ส่ง `{ perMinute: 30, perDay: 500 }` ให้ฟังก์ชันที่รับ `number` แล้วนำไปเทียบ `n > perMinute` การเทียบกับ object ได้ผล false
- หลักฐาน: typecheck แจ้ง TS2345 ทดสอบเรียก limiter ด้วย argument แบบเดียวกัน 501 ครั้งใน memory พบ blocked = 0
- ผลกระทบ: ไม่บังคับเพดานจำนวนคำขอใน `/api/turn` ทั้ง GET และ POST อย่างไรก็ตาม endpoint ยังตรวจ token อยู่ ไม่ได้แปลว่าคนไม่มีสิทธิ์ขอ credentials ได้
- แนวแก้: ทำ signature และการเรียกให้ตรงกัน ถ้าจะใช้ทั้งรายนาทีและรายวัน ต้องมี counter แยกจริง เพิ่ม test ให้คำขอเกินเพดานได้ 429
- ผลต่อดีไซน์: ไม่มี

### 3. P2 / HIGH: ฟอร์มล็อกอินไม่บอกว่ากรอกอะไรผิด

- กฎ: R-27 (error state), R-32 (accessibility)
- ตำแหน่ง: `web/site/src/routes/Login.tsx:79`, `web/site/src/routes/Signup.tsx:91`, `web/site/src/components/ui/Kit.tsx:33`
- หลักฐาน: กด Sign in เมื่อฟอร์มว่าง โฟกัสย้ายไป email แต่ไม่มีข้อความ `role=alert` และไม่มี `aria-invalid` แม้ schema ปฏิเสธข้อมูลแล้ว
- สาเหตุ: ใช้ `noValidate` และ resolver แต่ไม่ได้ส่ง `formState.errors` เข้า `Field` ที่รองรับ error อยู่แล้ว หน้า Signup/Forgot ก็มีช่องที่ไม่บอกสาเหตุ validation ขณะปุ่มถูกปิด
- แนวแก้: ใช้ Field เดิมแสดงข้อผิดพลาดภาษาไทย/อังกฤษใต้ช่อง เชื่อม `aria-describedby` และรักษาการ focus ช่องแรกที่ผิด ไม่เพิ่มระบบฟอร์มใหม่
- ผลต่อดีไซน์: เพิ่มข้อความอธิบายเฉพาะเมื่อกรอกผิด

## แนวทางคงดีไซน์เดิม

ไม่พบเหตุผลให้เปลี่ยน palette, ฟอนต์, wordmark, hero, ภาพปลั๊กอิน หรือโครงเรื่องของหน้าแรก ภาพสินค้าจริงและ MixDemo อธิบายความต่างระหว่างเสียงที่ผู้ใช้ฟังกับเสียงที่คนดูได้ยินได้ตรงประเด็น

กริดพื้นหลังเชื่อมกับหน้าปลั๊กอิน และปุ่มดำแยก action หลักจากข้อมูลรอบข้าง คงไว้ตามทิศทางที่ผู้ใช้กำหนด ความโค้งและพื้นผิวเดิมไม่ใช่บัค จึงไม่เสนอปรับทั้งหมดเพียงเพราะเป็น pattern ที่สกิลกล่าวถึง

การแก้ที่แนะนำเริ่มจากข้อ 1 จากนั้น 2–8 และ 10 ข้อ 9 ต้องใช้ข้อมูลจริงจากเจ้าของ ข้อ 11 ทำพร้อมข้อ 2 เพื่อตรวจพื้นที่ header ครั้งเดียว

## Delivery Gate ของสภาพเว็บที่ตรวจ

นี่คือรายงานตรวจ ไม่ใช่การส่งมอบดีไซน์ที่แก้เสร็จ สถานะ FAIL ด้านล่างคงไว้เป็นหลักฐานและรอเลือกหมายเลข ไม่ได้แก้ขัดกับโหมด after

- R-02: N/A ต่อการแก้ copy รอบนี้ ไม่ได้เขียนหรือปรับข้อความในเว็บ
- R-03: FAIL พบ header ล้นหลังล็อกอินที่ 320px และเป้าหมายแตะต่ำกว่าเกณฑ์สกิล (ข้อ 2, 11)
- R-17: ไม่รับรองตัวเลขความสามารถของปลั๊กอินจาก browser audit; ไม่ได้เพิ่มสถิติใหม่
- R-18: PASS เฉพาะหน้าที่ตรวจ ไม่มี testimonial section ที่สร้างบุคคลสมมติ
- R-23: PASS ไม่ได้สร้าง logo, avatar, ภาพ หรือ navigation ใหม่
- R-24: FAIL การนำทางบางจุดไม่รักษาภาษาที่เลือก (ข้อ 6)
- R-25: FAIL ลิงก์ในข้อความและป้ายจังหวะตามผล axe (ข้อ 8)
- R-26: FAIL limiter, player lifecycle, contact link และ sign-up next (ข้อ 1, 5, 9, 10)
- R-27: FAIL validation และ query error state (ข้อ 3, 4)
- R-28: PASS เฉพาะ FAQ ที่เห็น ถามเรื่องบัญชี การแยก mix ความหน่วง และ DAW ซึ่งเกี่ยวกับผลิตภัณฑ์
- R-32: FAIL feedback ของฟอร์มและภาษาเอกสาร; mobile menu Escape/คืน focus ผ่านเฉพาะที่ทดสอบ
- R-33: PASS ไม่มี script แก้ source/CSS ของแอป
- R-34: FAIL ปุ่มธีมมี state ไม่ตรงกัน แม้ตรวจ rendering ทั้ง light/dark แล้ว (ข้อ 7)
- R-35: PARTIAL build/test/browser ทำแล้ว แต่ typecheck ไม่ผ่าน และยังไม่ได้ทดสอบผู้ให้บริการจริงครบ flow
- R-36: ไม่รับรอง claims เรื่องเสียง/latency/compatibility จากการทดสอบเว็บนี้ ไม่ได้สร้าง claims ใหม่
- R-37: PASS สำหรับขอบเขตรายงาน ทิศทางคือรักษาดีไซน์เดิมตามผู้ใช้ ไม่ได้สร้างดีไซน์ใหม่หรืออ้างว่าผ่านการออกแบบใหม่
- R-38: FAIL contact placeholder ถูกใช้เป็นลิงก์จริง ส่วนเอกสารมีการติดป้าย draft อยู่แล้ว (ข้อ 9)
- Purpose Gate: คง grid, neutral palette, imagery และ hierarchy เดิมด้วยเหตุผลด้านความต่อเนื่องกับปลั๊กอิน; ไม่เพิ่มเทคนิคตกแต่ง
- Liveliness: ไม่ตั้ง dials ใหม่เพราะไม่ได้ออกแบบใหม่ ให้คง focal point ภาพปลั๊กอินและ CTA เดิม
- Craftsmanship C-2/C-4: FAIL ตามข้อ 1–11 ยังไม่ประกาศว่าเว็บพร้อมสมบูรณ์

## ข้อจำกัด

- ตรวจ local checkout ไม่ใช่ deployment จริง ไม่มีการ push หรือ deploy
- ไม่ส่งอีเมลจริง ไม่ทำ Google/Discord OAuth จริง ไม่ขอ TURN credentials จาก Cloudflare จริง และไม่เปลี่ยนข้อมูล production
- ไม่ทดสอบเสียงกับ Hub/ปลั๊กอินจริง, WebRTC ข้ามเครือข่าย, OBS หรือ installer เพราะเป็นคนละ runtime กับเว็บบัญชี
- ใช้ Chromium ผ่าน Microsoft Edge ในเครื่อง ยังไม่ได้ทดสอบ Safari, Firefox, iOS/Android จริง, screen reader หรือทุกปุ่มในหลังบ้านด้วยบัญชีผู้ดูแล
- typecheck failure แยกจาก build: Vite build ผ่านไม่ได้ยืนยันว่า TypeScript ทุกส่วนถูกต้อง
- ไฟล์ Rust และเอกสารแผนที่มีการเปลี่ยนแปลงก่อนเริ่มงานไม่ได้แตะต้อง
