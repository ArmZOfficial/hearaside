## API

- `strings`: `Str` (746 key), `tr`, `tr_in`, `trf`, `set_current_language`, `format_db`
- `Settings`: getter / setter ตาม key ของ C++; `set` แค่ mark dirty, ผู้ใช้เรียก `tick()` จาก timer (เขียนเมื่อการ
  เปลี่ยนเก่าสุดครบ 500 ms) หรือ `flush()`, Drop เขียนที่ค้าง
- `AccountManager::new(AccountConfig)`: device sign-in, `/me`, profile (`update_profile` ตรวจค่าก่อนส่ง), avatar,
  sign-out; event ถูกส่งให้ listener เมื่อผู้ใช้เรียก `dispatch_events()` บน thread ที่เลือกเอง; ไม่เปิดเผย
  `device_code` ให้ UI
- `ShareDirectory`: `update`, `stop`, `state`, `listen_url`, `send_url`, `origin`, `set_bearer`, `take_revoked`,
  `resolve(base, token)`
- Drop ของ `AccountManager` / `ShareDirectory` ห้ามเรียกใต้ loader lock (`DLL_PROCESS_DETACH`, static destructor)

## ไฟล์และรูปแบบ (สัญญาข้อ 3.4)

- ล็อก refresh ร่วมกับ C++: `Global\HEARASIDE_account_refresh` (Windows) / `fcntl` ที่ path แบบ JUCE (unix)

## ปรับให้ดีกว่า C++ (ไม่ใช่บั๊ก)

นาฬิกา monotonic สำหรับเวลาหมดอายุ code, 429 จาก share site รอแบบ 400 / 403, refresh ได้ 401 แล้ว sign out ในเครื่อง
ไม่เรียก revoke, รอ lock refresh มีเพดาน 25 s, register ใช้ snapshot ของ config, ไม่ register ซ้ำตอนตื่นครั้งแรก,
worker รอดจาก panic + lock ทน poisoning, event `RequestFailed`, ดูชนิดรูป avatar จากไบต์จริง, จำกัด `expires_in` /
`interval`, token ของ resolve รับแค่ `[A-Za-z0-9_-]`, บันทึกไฟล์ก่อนประกาศ signed in, cert store + proxy ของระบบ,
ตรวจ profile ก่อนส่ง, รอบ refresh แรกหลังเปิดเลื่อน 3 s (DAW ที่แค่สแกนไม่ยิงเน็ต), pin module เมื่อจำเป็นต้องปล่อย
worker (DLL ไม่ถูกถอดขณะ thread ยังวิ่ง), settings เขียนเฉพาะ key ที่เปลี่ยน

5. account API ทดสอบกับเซิร์ฟเวอร์ปลอมเท่านั้น, ยังไม่ได้อ่าน `account.dat` ที่ C++ เขียนจริง, ยังไม่ได้ทดสอบ C++ กับ Rust
   ใช้ lock / ไฟล์ร่วมกัน
6. ctest `share_directory` / `share_api` ยังรันกับ C++ (ฝั่ง Rust port เช็กครบแล้ว)
7. บั๊ก 81–105 ยังไม่ได้แก้ฝั่ง C++
