# ผลแก้เว็บ HEARASIDE

30 ตุลาคม 2026 · ต่อจาก [audit-001](audit-001-2026-10-30.md)

ผู้ใช้อนุมัติทั้ง 11 ข้อ และขอเพิ่ม local preview, ปรับ Admin, navbar/footer, ย่อคำอธิบาย, ภาพประกอบคู่มือ และตัวซูมภาพในเว็บ คงโทน สี ฟอนต์ และโครงหน้าเดิม ไม่มีการ push หรือ deploy

## ผลตามหมายเลขที่อนุมัติ

| ข้อ | ผลแก้ | หลักฐาน |
| --- | --- | --- |
| 1 | limiter รองรับทั้งตัวเลขเดิมและเพดานรายนาที/รายวัน | `limit.test.ts`: ครบ 500 คำขอข้ามหลายนาที, reset วันใหม่; `share.test.ts`: GET/POST ใช้เพดาน TURN ร่วมกัน |
| 2 | header พอดีจอหลังล็อกอิน มีขอบห่างหน้าจอ | E2E ตรวจ `scrollWidth <= innerWidth` ที่ 320px ทั้ง account และ Admin |
| 3 | Field แสดง validation error พร้อม `aria-invalid` และข้อความใต้ช่อง | unit + E2E กดส่งฟอร์มว่าง; Admin ตรวจรูปแบบเวอร์ชันและจำนวนก่อนบันทึก |
| 4 | แยก loading/error/empty ของ devices, links, friends และมีปุ่มลองใหม่ | E2E จำลอง 503 แล้วตรวจว่าไม่แสดง empty state |
| 5 | หยุดเดโมเมื่อออกจากหน้า กัน player ที่โหลดช้ากลับมาเล่น | unit ทดสอบทั้งกรณีเล่นแล้วและกำลังโหลด; E2E ตรวจ AudioContext ปิดหลังเปลี่ยนหน้า |
| 6 | ลิงก์ใช้ภาษาปัจจุบัน รวม auth, device flow และ Admin; sync `<html lang>` | unit + E2E เปลี่ยนภาษาและอนุมัติอุปกรณ์จากหน้าไทย |
| 7 | ThemeProvider แชร์ state ให้ทุกปุ่มและรับ storage event จาก tab อื่น | unit ตรวจปุ่มธีมสองจุดเปลี่ยนสถานะพร้อมกัน; browser ตรวจ light/dark |
| 8 | ลิงก์ในข้อความมีเส้นใต้ ป้ายจังหวะไม่รับ opacity จากเส้น | axe ไม่พบ violation ในหน้าที่สแกนหลังแก้ |
| 9 | ใช้ X: @armzchan00 ตามเจ้าของ ระบุวันที่แก้เอกสารจริง เอา placeholder ออก | หน้า privacy/terms ทั้งสองภาษาและ footer ใช้ ContactDetails เดียวกัน |
| 10 | ส่ง safe next และ locale ผ่าน email verification/reset | `authCallbackPath` unit test; callback ของ Supabase ต้อง allow URL ตามคู่มือก่อนใช้ production |
| 11 | ขยายปุ่มหลัก ภาษา ธีม เมนู avatar เดโม ตัวเลือกภาษา และลบเพื่อน | CSS กำหนดพื้นที่แตะหลัก 44px; จอ 320px ผ่าน browser tests |

ช่องรหัสอุปกรณ์ยังเป็นกลุ่ม 8 ช่องขนาดกะทัดรัดเพื่อใส่รหัสและวางรหัสทั้งชุดได้ ไม่อ้างว่าทุกส่วนย่อยของ OTP มีขนาด 44px

## งานที่เพิ่มตามคำขอ

- **Local:** `npm run dev:local` เปิด Vite + API memory ปิดบริการภายนอกและ CAPTCHA ในโหมดนี้ มีบัญชี `admin@example.test` และ `member@example.test` รหัส `HearasideLocal123!` ข้อมูลหายเมื่อ API restart
- **Rust:** [WEB-PLUGIN-CONTRACT.md](../docs/WEB-PLUGIN-CONTRACT.md) ระบุ path, JSON casing, token rotation, authorization, settings, share directory และ local setup ไม่มีการเปลี่ยนโค้ด C++/Rust หรือ audio protocol
- **Admin:** แยกตรวจสิทธิ์/ไม่มีสิทธิ์/โหลดผิดพลาด เพิ่ม refresh, กราฟพร้อมตารางรายวัน, ค้นหาผู้ใช้, ตารางที่แปลงเป็นรายการบนมือถือ และ dialog ยืนยันที่บังคับพิมพ์ handle ก่อนลบบัญชี
- **ข้อมูล Admin:** แก้ `last30` ให้รวมเฉพาะ 30 วันแม้กราฟแสดง 60 วัน และแยกยอด installer HEARASIDE จาก HAS Karaoke ในการดึง GitHub มี regression tests
- **Navbar/footer:** เว้นขอบจอ จัดลิงก์เป็นกลุ่ม ใช้ช่องทางติดต่อจริง และเพิ่มกลับขึ้นด้านบน
- **ข้อความ:** ย่อคำอธิบายไทย/อังกฤษ เก็บคำเตือนและเงื่อนไขที่จำเป็น เอาข้อความ coming soon ที่ล้าสมัยในคู่มือแชร์ออก และเลิกสัญญาว่าจะส่งอีเมลแจ้ง macOS ทั้งที่ไม่มี flow รองรับ
- **ภาพ:** ใช้ screenshot จริงจาก `ui-snapshots/friends` เพิ่ม App Audio และ Setup check ทั้งสองภาษา/ธีม ใช้ lossless WebP สำหรับ Hub เอาภาพที่ทับข้อความในการ์ดออกและแยกวางไว้เหนือคำอธิบาย
- **คู่มือ:** ทั้ง 5 เรื่องมีภาพพร้อมคำอธิบาย และแยกขั้นตอนยาว เช่น Studio One เป็นรายการทำตาม
- **ซูมภาพ:** เปิด native dialog ในหน้าเดิม มี +/−, ขนาดจริง, พอดีจอ, เปอร์เซ็นต์, ลากภาพ, wheel, pinch 2 นิ้ว, double click, keyboard +/−/0/1/ลูกศร, Escape และคืน focus ปิดแล้วคงตำแหน่งหน้าเดิม ไม่เปิดแท็บใหม่
- **Login อัตโนมัติ:** เข้าหน้าตั้งค่าหรือ `next` ทันทีหลัง login, ยืนยันอีเมล หรือบันทึกรหัสผ่านใหม่ ไม่ต้องกดปุ่ม Continue ซ้ำ รอ Google callback คืนปลายทางให้ครบก่อน redirect และยังแสดงข้อผิดพลาด callback แม้มี session เดิม
- **อัปเดตข้อมูลเอง:** อุปกรณ์ ลิงก์ และเพื่อนอัปเดตทุก 15 วินาทีขณะเปิดหน้า; Admin ทุก 30 วินาที รวมทั้งโหลดใหม่เมื่อกลับมา focus/online ไม่ retry การลบหรืออนุญาตปลั๊กอินเอง
- **ตรวจรหัสเอง:** กรอกรหัส 8 ตัวจากปลั๊กอินแล้วเว็บ lookup ให้ทันที กันคำตอบเก่าที่กลับมาช้าทับรหัสใหม่ และยังต้องกดอนุญาตเอง ไม่กรอกรหัสจาก URL อัตโนมัติ
- **ตำแหน่งและ animation:** จัด dialog รูป/ยืนยัน Admin ให้อยู่กึ่งกลางจอ จัดเมนูบัญชีไม่ให้ล้นมือถือ และคืน hero tilt ตามเมาส์ โดยล้าง transform เมื่อกลับมานิ่งเพื่อให้ภาพคมชัด เคารพ reduced motion และไม่ใช้ hover บนจอสัมผัส

## ผลทดสอบ

- `npm test`: **65 ผ่าน** ใน 10 ไฟล์
- `npm run test:plugin`: **31 ผ่าน** ใน 4 ไฟล์ เป็นส่วนหนึ่งของ 65 tests ไม่ได้นับซ้ำ
- `npm run test:e2e`: **21 ผ่าน, 1 ข้าม** ทั้ง desktop และ mobile 320px ธีมมืด โดย mobile ใช้ touch mode และ device scale factor 2; ข้ามเฉพาะ hover animation บนมือถือซึ่งไม่มีเมาส์
- ตัวซูมทดสอบ wheel ใน desktop และส่ง touch event 2 จุดจริงผ่าน CDP สำหรับ pinch ใน mobile รวมทั้ง pan, fit, actual size, no popup, Escape, คืน focus และปลด scroll lock
- หลังปรับ toolbar จอ 320px ให้ปุ่มอยู่แถวเดียว ทดสอบ zoom E2E อีก 2 กรณีผ่าน
- รอบสุดท้ายทดสอบ login/verify/reset ไปปลายทางเอง, live devices/reconnect, lookup ที่ตอบกลับผิดลำดับ และ browser approval ผ่านทั้ง desktop/mobile; ทดสอบตำแหน่ง dialog อยู่กลาง viewport และ hero tilt กลับเป็น `transform: none` เมื่อนิ่ง
- ตรวจภาพ desktop 1920×1080 เพิ่ม: dialog ขนาด 1280×1048 ที่ x=320, y=16 อยู่กลางจอทั้งสองแกน [ภาพ desktop](evidence/follow-up-001/image-viewer-desktop-centered.png), [ภาพ mobile 320px](evidence/follow-up-001/image-viewer-320.png)
- `npm run typecheck`: ผ่าน
- `npm run build`: ผ่าน client, SSR, prerender 20 หน้า มี warning เดิมเรื่อง main chunk เกิน budget 600 kB (ประมาณ 613 kB ก่อน gzip)
- `git diff --check -- web/site`: ผ่าน
- สแกน browser เพิ่ม **36 กรณี** ที่ 320, 390, 768, 1440px สลับ light/dark ไม่พบ horizontal overflow, page errors หรือ axe violations ในหน้าที่ตรวจ
- ในการทดสอบรอบกลางพบปุ่ม GitHub import ล้นที่ 320px แก้ให้ข้อความตัดบรรทัดแล้ว ตรวจ Admin ด้วย E2E รอบสุดท้ายผ่าน ไม่ใช้ผลรอบที่ล้มเหลวมาอ้างว่าผ่าน

## Delivery Gate

รายงานนี้ประเมินส่วนที่แก้ ไม่ใช่ใบรับรอง WCAG หรือการทดสอบ native plug-in

- R-02 PASS: ข้อความใหม่ใช้ประโยคสั้น ไม่มี em dash ใน UI copy ที่เพิ่ม
- R-03 PASS ในขอบเขตที่ตรวจ: สแกนหลายความกว้างและ E2E จอ 320px หลังล็อกอินไม่ล้น; toolbar zoom อยู่แถวเดียว
- R-17 PASS: Admin แสดงข้อมูลจาก API ไม่มีตัวเลขความนิยมแต่งขึ้น
- R-18 PASS: ไม่เพิ่ม testimonial หรือบุคคลสมมติบนหน้า public
- R-23 PASS: ใช้ภาพปลั๊กอินที่มีอยู่ ผู้ใช้ขอภาพประกอบและอนุมัติการปรับ navbar/footer; ไม่สร้าง logo ใหม่
- R-24 PASS: ลิงก์ภายในรักษาภาษา เพิ่ม alias หน้า Admin ภาษาไทย และติดต่อ X ตามที่เจ้าของระบุ
- R-25 PASS ในหน้าที่สแกน: axe 36 กรณีและ E2E ไม่พบปัญหา contrast/link distinction
- R-26 PASS สำหรับ flow ที่ทดสอบ: limiter, form, demo, image viewer, navigation, Admin และ device authorization ทำงานจริง
- R-27 PASS ในจุดที่แก้: error/retry ของ query และ validation มีข้อความชัดเจน; viewer โหลดภาพไม่สำเร็จมีข้อความ
- R-28 PASS: FAQ ยังเป็นเรื่องบัญชี เสียง DAW/OBS ความหน่วง และ DAW ที่รองรับ
- R-32 PASS สำหรับ keyboard ที่ทดสอบ: dialog Escape/คืน focus, menu Escape, ปุ่มซูม และ focus indicator; ไม่อ้างว่าทดสอบ screen reader จริงแล้ว
- R-33 PASS: แก้ source ด้วย patch โดยตรง ไม่ใช้ script แทนที่ CSS เพื่อสร้าง feature
- R-34 PASS ในธีมที่ทดสอบ: light/dark และ state ปุ่มธีมร่วมกัน
- R-35 PASS สำหรับ local: build/typecheck/unit/API/E2E ผ่าน มีหลักฐานคลิกจริงตามรายการด้านล่าง
- R-36 PASS: ไม่เพิ่มคำอ้าง security/performance certification และตัดข้อความแจ้งเตือน macOS ทางอีเมลที่ไม่มีระบบรองรับ
- R-37 PASS: ยึดดีไซน์เดิมตามผู้ใช้ การปรับ Admin ใช้ surface ทึบเพื่ออ่านข้อมูล ไม่เปลี่ยน palette หรือฟอนต์
- R-38 PASS ในเนื้อหาที่แก้: เอา contact/date placeholder ออก ภาพประกอบมาจาก snapshot จริง
- Purpose Gate PASS สำหรับส่วนใหม่: ใช้กราฟเพื่อเทียบจำนวน ตารางเพื่ออ่านค่าแน่นอน dialog เพื่อยืนยันผลกระทบ และ zoom เพื่ออ่านข้อความในภาพ ไม่เพิ่มการตกแต่งที่ไม่เกี่ยวกับงาน
- Liveliness: คง focal point ภาพปลั๊กอินและ CTA เดิม; ส่วน Admin ใช้ข้อมูลเป็นจุดนำ ไม่สร้าง visual direction ใหม่แทนแบรนด์
- C-1/C-2/C-3/C-4/C-5 PASS ตามขอบเขต: มีเหตุผลของส่วนที่เปลี่ยน ทุกปุ่มใหม่มี action, ไม่เพิ่ม section เปล่า, ตรวจ responsive/error/theme และไม่สร้าง social proof

หลักฐานคลิกจริง: ส่งฟอร์มว่าง → error ใต้ช่อง; เปลี่ยนภาษา → URL/ภาษาเอกสารเปลี่ยน; login local → account ทันที; verify/reset → กลับ next; กรอกรหัสครบ → แสดงรายละเอียด → อนุญาต → token ใช้งานได้; อุปกรณ์ใหม่ → รายการขึ้นเอง; offline/online → sync เอง; Admin revoke → access/refresh ใช้ไม่ได้; ฟอร์มยอดย้อนหลัง → ตรวจรูปแบบ/บันทึกได้; API 503 → error/retry; เดโม → Guides → audio ปิด; รูป → dialog กลางจอ → zoom/pan/pinch/fit → Escape → focus กลับ; คู่มือทั้ง 5 → เปิด/ปิดภาพได้; กลับขึ้นด้านบน → scroll กลับ 0; เมาส์บน hero → tilt → เอาเมาส์ออก → transform none

## ข้อจำกัดที่ยังต้องตรวจจริง

### ปรับคำอธิบายเพิ่มเติมตามคำขอ

- ย่อ release notes ทั้ง 11 เวอร์ชัน ไทย/อังกฤษ และแยกหนึ่งเรื่องต่อหนึ่งข้อใน “มีอะไรใหม่”
- ปรับคำอธิบายหน้าแรก ดาวน์โหลด สมัครบัญชี ข้อมูลบัญชี และ Admin ให้บอกการใช้งานตรง ๆ
- คู่มือไทยทั้ง 5 เรื่องอธิบายศัพท์ DAW/Master/Insert และแยกวิธีซิงก์เสียงเป็นขั้นตอน โดยคงภาพจริงและชื่อปุ่มไว้
- คง release notes เป็น string เหมือนเดิม ใช้ newline แบ่งข้อ และอัปเดต public release.json ทั้งสองสำเนาให้ตรงกัน
- PASS เนื้อหา: ตรวจเทียบกับต้นฉบับ ไม่เพิ่มฟีเจอร์หรือคำรับรองใหม่ ไม่เปลี่ยน version, วันที่, URL installer, ขนาดไฟล์ หรือ checksum; ตรวจด้วย assert เทียบ Git HEAD
- PASS ภาษา: ตัวแปรในข้อความแปลยังครบ ตรวจชื่อ placeholder เทียบต้นฉบับทั้งสองภาษา
- PASS layout/accessibility: browser scan 32 กรณี ครอบคลุมหน้าแรก ดาวน์โหลด สมัครบัญชี และ 5 คู่มือ สองภาษา ที่ 320px dark และ 1440px light ไม่พบ overflow, page errors หรือ axe violations
- PASS การแสดงผล: release notes ทั้ง 11 รุ่นแสดงเป็นรายการ รุ่นล่าสุดมี 7 ข้อทั้งสองภาษา [ภาพมือถือ](evidence/follow-up-001/copy-download-th-320.png)
- PASS การตรวจโค้ด: typecheck, Unit/API 65 tests, build และ prerender 20 หน้าผ่านหลังปรับข้อความ ไม่ได้รัน E2E ทั้งชุดซ้ำสำหรับงานข้อความรอบนี้

ข้อจำกัดของการทดสอบเดิมและการใช้งาน production:

- ไม่ได้ deploy, push หรือ commit งานนี้
- ยังไม่ทดสอบ Rust binary, DAW, audio engine หรือการร้องข้ามเครือข่ายจริง
- Email/OAuth/Cloudflare TURN production และรายการ Supabase Redirect URLs ยังต้องตรวจในบริการจริง คู่มือระบุสิ่งที่ต้องตั้งแล้ว
- STUN fallback ใน local ไม่ยืนยันว่า TURN relay ข้าม NAT ทำงาน
- ไม่ได้ทดสอบ Safari, Firefox หรืออุปกรณ์ iOS/Android จริง การตรวจมือถือใช้ Chromium touch emulation
- การแก้เอกสาร privacy/terms เป็นการปรับข้อมูลติดต่อ วันที่และข้อความเดิม ไม่ใช่การรับรองด้านกฎหมาย
