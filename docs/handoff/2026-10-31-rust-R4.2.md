# R4.2 — `hs-obs` remote (ปุ่มลัด OBS → Hub)

วันที่ 31 ตุลาคม 2026 · branch `rs/R4.2-obs-remote` (แตกจาก `ce0885e` = `rs/R3.3-share-server` ที่รวม R4.1 แล้ว) · commit ใน branch เท่านั้น ไม่ push · ยังไม่ผ่านรีวิว Opus ตาม PLAN 10.4 (ตารางสถานะ 0.4 ไม่ได้แก้)

## สถานะ

ปุ่มลัด `hearaside.mute_stream` และ `hearaside.preview` ทำงานแล้ว: กดแล้ว post คำสั่งเข้า remote queue ของ Hub ด้วยไบต์เดียวกับ C++ (พิสูจน์ด้วยการรัน `BusClient` ของ C++ จริงเทียบ ดูหัวข้อทดสอบ)

## ไฟล์

- `rust/crates/hs-obs/src/remote.rs`: `BusClient` (port ของ `obs/hearaside-obs/src/remote.{h,cpp}`) + ฟังก์ชัน `toggle_panic` / `toggle_preview` / `release_all` ที่ `module.rs` เรียกอยู่แล้ว (signature เดิม ไม่ต้องแก้ `module.rs`)
  - เก็บ mapping แบบ read/write ต่อชื่อ bus (`BTreeMap`), เปิดด้วย `SharedMemory::open_existing` (ไม่สร้าง bus เอง) และลองเปิดใหม่ได้ไม่เกินวินาทีละครั้งต่อ bus (เวลาลองล่าสุดตั้งก่อนเปิด และไม่ถูกล้างตอน `release_all` เหมือน C++)
  - ชื่อ bus ว่าง = `"Main"` เหมือน C++
  - toggle: อ่าน `hubFlags` (relaxed) ถ้าบิต `kHubPanic` / `kHubPreview` ตั้งอยู่ post `0.0` ไม่งั้น post `1.0` ด้วย `hs_bus::bus::post_remote(layout, -1, RemoteParam::Panic|Preview, v)` (ใช้ของเดิม ไม่เขียนคิวใหม่)
  - ล็อกเดียว (`Mutex`) ถือตลอดช่วงเปิด + post เหมือน C++; ไม่มี alloc/log บน audio thread เพราะไม่ได้อยู่บน audio thread เลย (ปุ่มลัดเรียกจาก hotkey thread ของ OBS; `module.rs` ครอบ `catch_unwind` อยู่แล้ว)
  - ไม่มี `unsafe` ใหม่
- `rust/crates/hs-obs/src/remote/tests.rs`: 12 test (ด้านล่าง)
- `rust/crates/hs-obs/src/lib.rs`: แก้คอมเมนต์หัวไฟล์
- `tests/integration/remote_probe.cpp` + 4 บรรทัดใน `tests/CMakeLists.txt`: โปรแกรมเครื่องมือ `ss_remote_probe` ที่ compile `obs/hearaside-obs/src/remote.cpp` ของจริง (ไม่ต้องใช้ libobs) มี 3 โหมด `toggle-panic <bus>`, `toggle-preview <bus>`, `poll <bus>` (`pollRemote` ฝั่ง Hub ของ C++ พิมพ์คำสั่งที่ถอดได้) ไม่ใช่ test ของ ctest และไม่ถูก link เข้า plug-in ใด ๆ
- ไม่แตะ shm layout, `kProtocolVersion`, wire, parameter ID, state format

## ทดสอบ

`cargo test -p hs-obs`: 35 ผ่าน (23 เดิมของ R4.1 + 12 ใหม่ของ `remote::tests`)

1. **unit / bus จริง (Rust)** — แต่ละ test สร้าง bus ของตัวเอง (ทำตัวเป็น Hub) แล้วกดปุ่มลัดผ่านฟังก์ชันที่ OBS callback เรียก แล้วอ่านไบต์ดิบ 4 ช่องของ entry (`seq, target, paramId, valueBits`):
   - mute: Hub ไม่ mute → `[1, 0xFFFFFFFF, 1, 0x3F800000]`; Hub mute อยู่ → `[2, 0xFFFFFFFF, 1, 0]`
   - preview: `[1, 0xFFFFFFFF, 2, 0x3F800000]` / `[2, 0xFFFFFFFF, 2, 0]`
   - แต่ละปุ่มดูเฉพาะบิตของตัวเอง (ทดสอบด้วย `!kHubPanic`, `!kHubPreview`, ทั้งสองบิต)
   - `poll_remote` ฝั่ง Hub ถอดได้ `(-1, 1, 1.0)`, `(-1, 2, 1.0)`
   - 4 thread กดพร้อมกัน 40 ครั้ง ไม่หายสักคำสั่ง
   - ไม่มี bus → ไม่ post ไม่สร้าง segment; ลองเปิดใหม่ได้ไม่เกิน 1 ครั้ง/วินาที (ส่งนาฬิกาเข้า `with_at` ไม่ต้องรอจริง); `release_all` แล้วเวลา retry ยังอยู่; bus คนละชื่อไม่ปนกัน
2. **ข้ามภาษา C++ ↔ Rust** (ตั้ง `SS_REMOTE_CPP` ชี้ไปที่ `ss_remote_probe.exe` ไม่ตั้งก็ print "skipped" เหมือน `SS_IPC_CPP` ของ hs-bus):
   - `cpp_hotkeys_and_rust_hotkeys_write_identical_queue_bytes`: สอง bus ที่ Rust สร้าง bus หนึ่งให้ C++ `BusClient` กดปุ่ม อีก bus ให้ Rust กดปุ่ม ทีละ `hubFlags` 5 แบบ (0, Panic, Preview, ทั้งคู่, ทุกบิต) เทียบ `remoteReserve` และทุก entry ไบต์ต่อไบต์ ตรงกันหมด 10 คำสั่ง
   - `cpp_probe_with_no_bus_posts_nothing_and_creates_nothing`
   - `cpp_hub_side_poll_remote_reads_the_rust_commands`: C++ `pollRemote` อ่านคำสั่งที่ Rust post ได้ `cmd -1 1 3f800000`, `-1 2 3f800000`, `-1 1 00000000`, `-1 2 00000000`
   - รันจริงแล้วทั้งสองเส้นทาง exe (probe ที่ build แยกใน scratchpad และ target `ss_remote_probe` จาก `tests/CMakeLists.txt` ของ repo build ผ่านด้วย VS 2022) ผ่าน 12/12; ไม่ตั้ง env ผ่านโดยข้าม 3 test
3. `cargo test --workspace --locked`: ผ่านทั้งหมด (ทุกบรรทัด `test result: ok`, 0 ตก, ตั้ง `SS_REMOTE_CPP` ไว้) · `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo fmt --all -- --check`, `cargo deny --locked check licenses bans sources`: ผ่าน
4. ไม่มี crate ใหม่ใน `Cargo.lock`

## บั๊ก C++ ที่แก้

ไม่มีในงานนี้ (ไม่พบบั๊กใน `remote.cpp`) ข้อสังเกตที่ **ไม่ได้แก้** เพราะเป็นพฤติกรรมในสัญญา: toggle อ่านสถานะ Hub แล้วค่อย post (read-then-post) ถ้ากดสองครั้งติดกันก่อนที่ Hub จะ poll ทั้งสองครั้งจะ post ค่าเดียวกัน; ทั้ง C++ และ Rust เป็นแบบนี้. ที่ต่างจาก C++ เล็กน้อยโดยไม่เปลี่ยนไบต์ที่เขียน: ถ้า mutex ถูก poison (panic ระหว่างถือล็อก) Rust ใช้ต่อ ไม่ panic ซ้ำทุกครั้งที่กด

## ที่ข้าม / ยังไม่ได้ตรวจ

1. **ไม่ได้กดปุ่มลัดผ่าน libobs จริง**: ตรวจที่ระดับ `remote.rs` (ฟังก์ชันที่ `hk_panic` / `hk_preview` เรียก) กับ bus จริง; ส่วน `module.rs` ที่ลงทะเบียน hotkey (R4.1, ไม่ถูก compile ใน `cargo test`) ไม่ได้แก้และไม่ได้ลอง trigger hotkey ผ่าน `obs_smoke.c` / OBS GUI / Stream Deck. ไม่ได้รันกับ Hub (DAW) ตัวจริงว่า Hub สลับ mute/preview ตามคำสั่ง (ฝั่ง Hub อ่านด้วย `poll_remote` ที่มี test ใน hs-bus อยู่แล้ว)
2. test ข้ามภาษาต้องมี exe: CI ยังไม่ตั้ง `SS_REMOTE_CPP` (เหมือน `SS_IPC_CPP` ที่ยังไม่ได้ตั้งใน CI); ในเครื่อง build ได้ด้วย `cmake --build <build> --target ss_remote_probe`. ไม่ได้รันบน Linux/macOS (shm POSIX, `ss_remote_probe` ตรงนั้นใช้ `shm_posix.cpp`)
3. ไม่ได้วัดว่าปุ่มลัดบล็อก hotkey thread นานแค่ไหนตอน Hub กำลัง init (ช่วงที่ `open_existing` รอ magic สูงสุด 200 ms ใต้ล็อก, เหมือน C++)
4. worktree นี้ไม่มี `external/*` (submodule) จึงทำ junction ไป `Hearaside plugin\external\*` เพื่อ build (ไม่ได้ commit); build C++ ทั้ง repo (`HEARASIDE_BUILD_PLUGINS=OFF`) generate ฟ้อง target `HearasideAppAudio_VST3` ไม่พบ ซึ่งไม่เกี่ยวกับงานนี้ แต่ target `ss_remote_probe` build ได้
5. ไม่ได้รัน `ss_unit_tests` ของ C++ (ไม่ได้แตะโค้ด libs/*)
