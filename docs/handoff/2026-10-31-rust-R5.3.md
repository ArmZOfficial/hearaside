## สถานะ

crate ใหม่ `rust/crates/hs-karaoke` (lib; ตัว .exe มาใน R5.5) port จาก `apps/karaoke/` 4 คลาส:

| ไฟล์ Rust | ต้นทาง C++ | สรุป |
|---|---|---|
| `src/vocal.rs` | `VocalChain.{h,cpp}` | gate, biquad 3 ตัว (TDF-II ตามสูตรของ JUCE), compressor 3:1, Freeverb (tuning ของ Jezar ซึ่งเป็น public domain + smoothing 10 ms + `+0.1-0.1` denormal flush แบบ JUCE บน x86), echo ping-pong. ตัวควบคุมอยู่ใน `Arc<VocalParams>` (atomics แบบ C++) |
| `src/player.rs` | `MusicPlayer.{h,cpp}` (โหมด AudioFile) | `music_player(rate) -> (MusicPlayer, MusicOutput)`: เธรดถอดรหัส (`symphonia` + `hs_dsp::resampler::VarResampler`) เติม ring แบบ atomics, audio thread แค่คัดลอก. seek / stop / เปลี่ยนเพลง ใช้เลข generation: audio thread ทิ้งของเก่าใน ring เมื่อเธรดถอดรหัสยืนยันว่าหยุดเขียนตำแหน่งเก่าแล้ว. จบเพลง → `poll()` ไปเพลงถัดไป (วนเหมือน C++) |
| `src/preflight.rs` | `PreflightChecker.{h,cpp}` | `preflight(rate) -> (PreflightChecker, PreflightAudio)`: state IDLE / ARMED / RUNNING / DONE, `poll()` จาก timer ของ UI วิเคราะห์ผล. `evaluate()` ตรงกับ C++ ทุกข้อความ |
| `src/update.rs` | `UpdateChecker.{h,cpp}` | `compare_versions`, `release_info` (อ่าน JSON), `check_for_updates` (เธรดแยก เรียก callback บนเธรดนั้น ให้ผู้เรียกส่งต่อเข้า UI แบบ `hs-app`). version มาจาก `CMakeLists.txt` ผ่าน `build.rs` เหมือน `hs-obs` |

ไฟล์อื่น: `hs-app/src/http.rs` เพิ่ม `pub fn get_json` (GET JSON ไม่มี secret ผ่าน client เดิม) · `rust/Cargo.toml` (member) · `rust/deny.toml` เพิ่ม MPL-2.0 ให้ `symphonia` (มีในภาคผนวก A อยู่แล้ว) · `rust/Cargo.lock` · `tools/compat-vocal-golden/main.cpp` เพิ่มโหมด `--render` สำหรับฟัง A/B · `examples/vocal_render.rs` (คู่ของ `--render` ฝั่ง Rust). ไม่แตะ shm layout, wire, parameter ID, state format

## บั๊ก C++ ที่แก้ใน Rust (9 ข้อ)

1. **MusicPlayer อ่านไฟล์ + ถอดรหัส + ถือ lock ใน audio thread**: `AudioTransportSource` ไม่มี read-ahead thread และใช้ `CriticalSection` (ผิด Hard rule 1, ดิสก์ช้า = เสียงกระตุก). Rust: เธรดถอดรหัส + ring ไม่มี lock (`rt_safety` 0 alloc)
2. **VocalChain: block ที่ยาวกว่าที่ `prepare` ไว้** ประมวลผลแค่ส่วนแรก ส่วนที่เหลือของ output ค้างค่าเก่า (เสียงซ้ำ/ดังกระชาก). Rust: ทำทีละช่วงจนครบ (test `a_block_longer_than_prepared_is_processed_whole`)
3. **VocalChain: `numSamples` ติดลบ** ไป `memset` ขนาดมหาศาล. Rust ใช้ `usize` + slice ไม่เกิด
4. **Preflight: `callAsync([this] ...)`** ถ้าลบ checker ก่อน callback รัน = use-after-free. Rust: `poll()` ไม่มี callback ค้าง
5. **Preflight: `startCheck` ล้างบัฟเฟอร์/ตำแหน่ง** ขณะ audio thread อาจยังเขียนอยู่ (data race). Rust: UI แค่ตั้ง ARMED, audio thread rewind เอง
6. **Preflight: ผลวิเคราะห์ของรอบเก่า** (ยกเลิก/เริ่มใหม่) ทับผลของรอบใหม่. Rust: CAS DONE→IDLE ได้ผลครั้งเดียวต่อรอบ (test `restart_and_cancel_during_a_check`)
7. **Preflight `evaluate`: mic สั้นกว่า chirp** ยังรัน lag 0 = อ่านเกินบัฟเฟอร์. Rust: correlation 0
8. **MusicPlayer `removeTrack` เพลงที่เล่นอยู่** ไม่ล้างความยาวเพลง (UI โชว์ค่าเก่า)
9. **Freeverb ที่ sample rate < ~40 Hz** ขนาด comb = 0 → หารด้วยศูนย์. Rust ขั้นต่ำ 1

แก้หลังรีวิว: seek เกินท้ายเพลง (symphonia ปฏิเสธ = เล่นต่อที่เดิม) และไฟล์ที่ probe ได้แต่ถอดรหัสไม่ได้ ตอนนี้ "จบเพลง" ทันทีให้ `poll()` ไปเพลงถัดไป (C++ ก็เงียบแล้วไปต่อ / ไม่เริ่มเพลงนั้น); เช็กจบเพลงอ่าน `write` และ `generation` ใหม่ (กันตัดท้ายเพลง และกัน seek ที่เพิ่งกดถูกยกเลิก); เธรดถอดรหัสไม่ตื่นทุก 5 ms เมื่อไม่มีเพลง

## ต่างจาก C++ โดยตั้งใจ

1. headphone L/R เขียนแยกกันได้ (C++ เขียนเฉพาะเมื่อมีทั้งคู่)
2. ผลของ Preflight และการไปเพลงถัดไปต้องเรียก `poll()` จาก timer ของ UI (~100 ms) แทน `callAsync` / ChangeListener; UpdateChecker เรียก callback บนเธรด worker
3. เปลี่ยน sample rate = สร้าง `music_player` / `preflight` คู่ใหม่ (playlist ต้อง add ใหม่; C++ `prepare` ซ้ำได้). R5.4 ตัดสินว่าจะเพิ่มคำสั่งเปลี่ยน rate หรือไม่
4. เพลงเริ่มเล่นช้ากว่า C++ หนึ่งรอบปลุกเธรดถอดรหัส (ปกติ < 1 callback)
5. resampler เป็น Speex quality 5 (`hs-dsp`) แทน `ResamplingAudioSource` ของ JUCE: ไม่ตรงทุกบิต ให้ฟังเทียบ
6. ไม่มี `onTrackChanged` / `onPlaybackStateChanged` (R5.5 อ่าน state บน timer)

## ยังไม่ได้ทำ / ข้อสังเกตให้ ArmZ ตัดสิน

1. **AppCapture** (เพลงจากแอปอื่นผ่าน WASAPI process loopback) ไม่ได้ port: เป็นของ `hs-win` คู่กับ App Audio (R7)
2. รูปแบบไฟล์: WAV, AIFF, FLAC, Ogg Vorbis, MP3, M4A/AAC (LC) ผ่าน `symphonia`. **WMA และ HE-AAC/ALAC ไม่รองรับ** (C++ ได้จาก Media Foundation) ไฟล์แบบนี้จะข้ามไปเพลงถัดไป
3. MP3 ที่ไม่มี Xing/LAME header แสดงความยาว 0 (`shortcut:` ใน `probe_length`)
4. ข้อความของ Preflight เป็นไทยอย่างเดียวเหมือน C++ (ไม่อยู่ใน `Strings.cpp`) ควรย้ายเข้า `hs-app::strings` ตอน R5.5
5. UpdateChecker: `installer` ใน `release.json` เป็น path สัมพัทธ์ (`/downloads/...`) C++ รับเฉพาะที่ขึ้นต้น `http` จึงพาไปหน้า download เสมอ (Rust ทำเหมือนกัน). ถ้าอยากให้โหลดตรง ต้องตัดสินว่าจะใช้ `installer` หรือ `karaokeInstaller`

## ฟังเทียบ A/B (ต้องทำด้วยหู)

ใช้ไฟล์เสียงร้องจริง (WAV 48 kHz, ไมค์แห้ง ไม่มี effect) แล้ว render ผ่านทั้งสองฝั่งด้วยค่าเริ่มต้นของแอป (reverb 0.25, echo 0.20, gate -45 dB):

```powershell
cmake -S tools/compat-vocal-golden -B build/compat-vocal-golden -A x64
cmake --build build/compat-vocal-golden --config Release --target hs-vocal-golden
build/compat-vocal-golden/Release/hs-vocal-golden.exe --render voice.wav ab-cpp.wav
cd rust; cargo run --release -p hs-karaoke --example vocal_render -- ..\voice.wav ..\ab-rust.wav
```

ฟัง `ab-cpp.wav` กับ `ab-rust.wav` สลับกันโดยไม่ดูชื่อ. ตรวจแล้วบนเครื่องนี้ด้วยเสียงสังเคราะห์ 4 วินาที (ฮาร์มอนิก 7 ตัว + noise): **สองไฟล์ตรงกันทุกบิต (ต่างกันสูงสุด 0)** และ `hs-vocal-golden --compare` ยังผ่าน (error 0) จึงควรแยกไม่ออก แต่ยังไม่ได้ลองกับเสียงร้องจริงและยังไม่มีคนฟัง. MusicPlayer: เปิดเพลง 44.1 kHz ใน HAS Karaoke C++ เทียบกับ Rust หลัง R5.4 เสียบ device แล้ว (resampler ต่างตัว)
