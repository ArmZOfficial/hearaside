# R3.3 — Rust ShareServer

## สถานะ

R3.3 เสร็จฝั่ง Rust: `hs_net::share::ShareServer` port จาก `plugins/common/ShareServer.{h,cpp}` ครบ (HTTP + WebSocket,
token, Origin, จำกัดการเชื่อมต่อ, listener / send-in / friend session, คิวส่งจำกัดขนาด + เธรดส่งแยกต่อเพื่อน,
WebRTC signaling ผ่าน `hs_net::rtc`, cloudflared + job object, LAN / Radmin) builder (Sonnet high) ทำ, fresh reviewer
(Opus) ตรวจตาม PLAN 10.4 ได้ BUG 1 + RISK 3 + NIT 8 แก้ครบพร้อม test แล้ว ยังไม่ได้ลองกับเบราว์เซอร์ / DAW /
cloudflared ตัวจริง (R3.6 จะรัน `tests/web-friend/*.mjs` กับตัว Rust)

## C++ bugs fixed in Rust (ledger ต่อจาก 40 ใน `2026-10-29-rust-r0.md`)

41. `stop()` ปิด socket ขณะเธรดเชื่อมต่อยังใช้ fd อยู่ (OS เอา fd ไปใช้ใหม่ได้): Rust `shutdown(Both)` แล้ว join ก่อน drop
42. Linux: ปิด listener ไม่ปลุก `accept()`: Rust ใช้ listener แบบ non-blocking poll ทุก 50 ms
43. callback WebRTC ต่อท้ายคิวส่งของ listener โดยไม่ล็อก: Rust ใช้คิวเดียวที่มี mutex
44. callback ของ libdatachannel จับตัวแปร local ของ session ไว้ด้วย reference (อยู่นานกว่า session): Rust ให้ peer มีเธรดของตัวเองและ state เป็น Arc
45. เทียบ token แบบไม่ constant-time: Rust เทียบ constant-time และวนทั้งตารางเพื่อน
46. token ว่างตรงกับ `/l/` และ `/s/`: token ว่าง = ไม่มีลิงก์
47. Origin ยอมแค่ LAN IP ตัวเดียว (เปิดผ่าน Radmin / NIC ที่สองได้ 403): ยอมทุก IPv4 ของเครื่องและ `[::1]`
48. 172.x สาธารณะถูกนับเป็น LAN: นับเฉพาะ 172.16/12
49. บรรทัด error `Post "https://api.trycloudflare.com/tunnel"` ถูกอ่านเป็น URL จน tunnel ขึ้น Ready: ตัด `api` ออก และไม่รับ `comx`
50. ping / pong จาก client ทำให้การเชื่อมต่อหลุดหลัง timeout 1–5 วินาที: ตอบแล้วกลับไปรอต่อ
51. HRA3 `frames = 60000` เขียน concealment ขนาดนั้น 10 รอบลง ring ของเพื่อน: รับเฉพาะ 1..=5760
52. request head เกิน 8 KiB ถูกประมวลผลแบบถูกตัด: ตอบ 431 แล้วปิด
53. นับเพดาน listener แบบตรวจก่อนนับ (race): นับก่อนแล้วตรวจ
54. listener แบบ Opus ส่ง 1 packet (10 ms) ต่อรอบที่กินเวลา ≥ 10 ms จน lag สะสมถึงการกระโดด 2 วินาที: ส่งเป็นชุดได้ถึง 8 packet เมื่อช้า
55. slot เพื่อนนอกช่วง 0..8 ทำให้ index เกิน array: ข้ามรายการนั้น
56. u64 underflow ใน `w - rate/10` และ `mw - 960` ตอนตำแหน่งเขียนยังน้อย: `saturating_sub`
57. WebSocket: frame ที่อ้าง 4 MiB จองหน่วยความจำ 4 MiB ทันที: อ่านเป็นช่วง; RSV bits, control frame ที่แบ่งส่ง, opcode สงวน: ปิดการเชื่อมต่อ
58. `FriendEcho` สร้างแบบ lazy โดยไม่ล็อก: `Mutex<FriendEcho>` ต่อ slot
59. ตัวนับ listener / sender / friend รั่วเมื่อ panic: ใช้ guard
60. JSON control ขนาดเกิน 64 KiB ถูก parse: ไม่ parse
61. delay เป็น NaN ถูกส่งเป็น NaN: ส่ง -1.0
62. (จากรีวิว) newest-wins: session เก่าเขียน `kFriendOffline` ทับหลัง session ใหม่ขึ้น Live ได้ (slot ขึ้นออฟไลน์ทั้งที่ต่ออยู่): bump generation + Live store อยู่ใต้ `friend_write` เดียวกับการตรวจของ session เก่า
63. (จากรีวิว) HRA1 / HRA2 PCM ขนาดใหญ่ (เช่น 4 MiB) เขียน ~2M frames ลง ring ในครั้งเดียว: จำกัด 5760 frames (นับจาก body จริง)
64. (จากรีวิว) macOS: SIGPIPE ตอนเบราว์เซอร์ปิดกลางทางทำให้ DAW ปิดตาม (Rust ใน cdylib ไม่ ignore ให้): ignore SIGPIPE ใน `start()` และตั้ง `SO_NOSIGPIPE` ให้ socket ที่ accept บน Apple

## Review fixes ที่ไม่ใช่บั๊ก C++

- BUG (Rust เอง): เธรด RTC อาจอยู่หลัง `stop()` ถ้า DNS ของ STUN ค้าง (DLL ถูก unload ขณะเธรดยังวิ่ง = DAW ล่ม):
  resolve ชื่อ STUN ครั้งเดียวต่อ `start()` บนเธรด `share-dns` ที่ `stop()` join; peer ได้แต่ IP ไม่ทำ DNS เอง;
  `RtcWorker::shutdown` join เสมอ ข้อจำกัด: ถ้า `getaddrinfo` ค้าง `stop()` จะรอจนมันคืน (ไม่ detach)
- `wait_readable` ทิ้งข้อมูลก่อน FIN เมื่อ POLLHUP ติดมาด้วย: ถือว่าอ่านได้เมื่อมีบิต read
- `pong_value` ไม่มีตัวเลข = ไม่นับ, ไม่ zero `friend_queue_bytes` ของ session ที่ยังเป็นตัวจริง, JSON escape ตาม
  JUCE 8.0.15 (`< 32` เท่านั้น), `AtomicF32` เป็น SeqCst ตาม C++, pin `getrandom` / `serde_json`

## ข้อแตกต่างจาก C++ (ตั้งใจ)

- JSON control อ่านด้วย `serde_json` (เข้มกว่า JUCE) แต่ข้อความทุกตัวที่ `listen.html` / `send.html` ส่ง parse ได้
  (reviewer ตรวจแล้ว) ข้อความขาออกเว้นวรรคแบบ JUCE (`": "`, `", "`)
- cloudflared ถูกใส่ job object ทันทีหลัง spawn (C++ สร้างแบบ suspended), ตั้ง TCP_NODELAY, peer RTC อยู่บนเธรด
  ของตัวเองต่อ session, เธรดส่งของเพื่อนหยุดเมื่อไม่ใช่ session ล่าสุดหรือถูก kick
