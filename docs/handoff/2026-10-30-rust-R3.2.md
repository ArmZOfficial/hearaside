# R3.2 — Rust WebRTC transport

วันที่ 30 ตุลาคม 2026 · branch `rs/R3.2-webrtc` · ไม่มี commit / push / publish

## สถานะ

R3.2 ฝั่ง transport และ desktop Chrome ผ่านแล้ว รีวิวแยกตาม PLAN 10.4 จบโดยไม่มีข้อที่ต้องแก้เพิ่ม รุ่น Opus/Sonnet ตามแผนไม่มีในเครื่องมือ จึงใช้โมเดลที่มีโดยแยก builder และ fresh reviewer งาน R3.3 ShareServer ยังไม่เริ่ม

มีงาน R1/R2/R3.1 และเว็บที่ยังไม่ commit อยู่ก่อนเริ่มงานนี้ ห้าม reset/stash หรือรวมทั้งหมดเป็น diff ของ R3.2

## ไฟล์ในงานนี้

- `rust/crates/hs-net/src/rtc.rs`: peer แบบ single owner ให้ network worker เรียก `poll()`; enumerate NIC/LAN/Radmin, bind ช่วงพอร์ต, SDP/ICE, UDP STUN IPv4/IPv6, DataChannel unordered / maxRetransmits 0, ส่ง binary โดยไม่เปลี่ยน HRA payload
- `rust/crates/hs-net/src/lib.rs`, `Cargo.toml`, `rust/Cargo.lock`: expose peer, ปัก `str0m =0.24.1` backend `aws-lc-rs` และ `if-addrs =0.15.0`; `serde_json` ใช้ใน test driver
- `rust/crates/hs-net/tests/rtc.rs`: port loopback C++ พร้อมทดสอบ signaling, port lifecycle, STUN gathering/replay, candidate bounds, rogue UDP และส่ง HRA3 สองทิศ
- `rust/crates/hs-net/examples/rtc-peer.rs`: JSON-lines adapter สำหรับทดสอบ ไม่ใช่ production ShareServer
- `rust/crates/hs-net/build.rs`: สร้าง `opus-target.cmake` ผ่าน `CMAKE_PROJECT_Opus_INCLUDE` ให้ Opus เลือก SIMD ตาม Cargo target แม้ desktop shell ไม่มี `PROCESSOR_ARCHITECTURE` หรือ CMake cache เก็บ processor ว่าง; ไม่แก้ golden fixture
- `tests/web-friend/rtc.test.mjs`: HTTP/WebSocket fixture เปิดหน้า HTML เดิมใน Chrome แล้วต่อกับ Rust ผ่าน UDP จริง ใช้ WebSocket server ที่ bundle กับ Playwright เดิม ไม่มี Node dependency ใหม่
- `rust/deny.toml`: เพิ่ม Apache-2.0, ISC, BSD-3-Clause, Unicode-3.0 ตาม license ของ dependency ใหม่
- `rust/README.md`, `docs/PLAN-rust-migration.md`: วิธีใช้ / ตรวจ / สถานะ

ไม่มีการแก้ C++ production, HTML, wire format, shm v14, parameter ID, state หรือ FFI ใน R3.2; `hs-net` ยังไม่ถูก link เข้า `hs-ffi`

## ข้อจำกัดและขั้นต่อไป

1. ทดสอบเฉพาะ desktop Chrome บน Windows ยังไม่ตรวจ mobile Safari, Internet NAT จริง, TURN relay-only, loss/jitter/reorder ผ่าน UDP, Linux/macOS หรือ DAW/OBS จริง และไม่ได้รัน `build.ps1 -Test` ชุดเต็ม
2. Rust gather เฉพาะ host และ UDP STUN; configured `turn:`, `turns:`, `stuns:` คืน `Unsupported` ไม่ได้เงียบแล้วละทิ้ง config ส่วน browser-side TURN ยังใช้ได้ตาม signaling แต่ยังไม่ได้ยืนยัน relay จริง C++ Hub ปัจจุบันส่ง config เฉพาะ UDP STUN สองตัว ไม่มี authenticated STUN ใน Rust
3. Constructor ทำ DNS/socket/crypto บน network worker; `poll`, `send`, `close`, Drop ห้ามเรียกบน audio thread
4. Full advisory scan ของ `cargo deny --locked check` ถูกขวางด้วย cargo-deny รุ่นติดตั้งที่อ่าน CVSS 4.0 ของ RustSec `RUSTSEC-2026-0146` ไม่ได้ ไม่ใช่ผลยืนยันว่าพบ crate ดังกล่าวใน dependency tree และไม่ได้แก้ advisory DB หรืออัปเกรดเครื่องมือ global ผล licenses/bans/sources ด้านบนใช้ได้ตามปกติ
5. ต่อ R3.3: ใช้ events ของ `RtcPeer` กับ signaling เดิมใน ShareServer worker, HTTP/WebSocket token/Origin, per-friend bounded send queue และ cloudflared ตามแผน ตัวทดสอบครั้งนี้เป็น transport fixture ไม่ใช่เซิร์ฟเวอร์ production หรือ `hs-testkit` R3.6
6. ก่อน link Rust net กับปลั๊กอิน ต้องเลือก Opus/Speex C ชุดเดียวกับ `ssnet` เพื่อไม่ให้ symbol ซ้ำ ตามข้อค้าง R3.1 ไม่ได้แก้ด้วยการ link ทั้งสองชุดในงานนี้
