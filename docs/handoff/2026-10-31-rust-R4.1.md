# R4.1 — `hs-obs` (OBS source เป็น Rust)

วันที่ 31 ตุลาคม 2026 · branch `rs/R4.1-hs-obs` (แตกจาก `a32eae5` บน `rs/R3.3-share-server`) · commit ใน branch เท่านั้น ไม่ push / publish · ยังไม่ผ่านรีวิว Opus ตาม PLAN 10.4 (ตารางสถานะ 0.4 ไม่ได้แก้)

## สถานะ

`cargo build -p hs-obs --release` ได้ `rust/target/release/hs_obs.dll` ที่ export 7 ชื่อเดียวกับ DLL ของ C++ (`obs_module_author/description/load/name/set_pointer/unload/ver`)
โหลดเข้า libobs จริงได้ (OBS ที่ติดตั้งในเครื่องคือ libobs 33.0.0, ไม่ใช่ 32.2.2) และรับเสียงจาก Hub (Rust) ได้ ดูหัวข้อ "ทดสอบกับ libobs จริง"
**ปุ่มลัด `hearaside.mute_stream` / `hearaside.preview` ลงทะเบียนครบทั้งชื่อและข้อความ แต่กดแล้วยังไม่ทำอะไร** (R4.2 ยังไม่ทำ)

## ตัดสินใจ

1. **ไม่ใช้ bindgen / crate `libobs`**: bindgen ต้องมี libclang ตอน build (เครื่องนี้และ CI ไม่มี) แต่ module ใช้ฟังก์ชันราว 30 ตัวกับ struct 2 ตัว จึงเขียน FFI มือ แล้วให้ `const` assert + `tools/layout_probe.c` (compile กับ header จริงด้วย MSVC) เป็นหลักฐานของ layout
2. **ลิงก์ `obs.dll` ด้วย `raw-dylib`** ไม่ต้องสร้าง `obs.lib` จาก `dumpbin` เหมือน CMake ผลเท่ากัน (import จาก `obs.dll` ตามชื่อ) และ build ได้แม้เครื่องไม่มี OBS บน non-Windows ไม่ใส่ `link` เลย (host โหลด libobs อยู่แล้ว) — **ยังไม่ได้ลองลิงก์บน Linux / macOS**
3. **ข้อความ UI อยู่ใน `hs-obs` เอง ไม่ใช่ `hs-app::strings`**: ข้อความเหล่านี้เป็นคู่ `T(en, th)` ในไฟล์ C++ ที่เลือกภาษาจาก locale ของ OBS (ไม่ใช่ค่าตั้งของ HEARASIDE) ไม่เคยอยู่ใน `Strings.cpp` และ `hs-app` ลาก `ureq` / `rustls` / `aws-lc` เข้ามาใน DLL ที่ R4.4 ต้องการให้เบา ข้อความทุกคำคัดลอกตรง และ test เทียบกับ `plugin.cpp` สองทาง
4. **ชื่อไฟล์ DLL**: cargo ได้ `hs_obs.dll`; ตอนติดตั้ง (R4.3 / R9) ต้อง copy เป็น `hearaside-obs.dll` ให้ตรงกับของเดิม
5. ลำดับในลูป ตัวเลข timestamp, ค่า 5 ms / 20 ms / 200 ms / 1/8 ตรงกับ C++ ทุกตัว

## บั๊ก C++ ที่แก้ใน Rust (ส่วนที่ไม่อยู่ในสัญญาข้อ 3)

1. **หารด้วยศูนย์**: `Source::run` หาร `1e9 / rate` เมื่อ OBS ยังไม่มี audio (rate = 0) → C++ crash; Rust ใช้ 48 kHz แทน (OBS resample เองจาก `samples_per_sec` ของแต่ละบล็อก) test: `feeder_rate_zero_falls_back_to_48k`
2. **lock + alloc ในลูปป้อนเสียง**: C++ ล็อก `cfgMutex` ทุก 5 ms และคัดลอก `ConsumerStatus` (มี `std::string` 2 ตัว) ใต้ `statusMutex` ทุก tick; Rust ล็อกเฉพาะตอน settings เปลี่ยน (ตัวนับ atomic) และส่ง status เป็น atomics (`StatusCell`) ไม่ alloc หลังต่อ Hub ได้ test: `feeder_delivers_..._allocates_nothing_once_connected` (counting allocator นับ 0 และพิสูจน์ว่า counter เห็นการ alloc ตอนต่อครั้งแรก)
3. **ตัวเลขใน settings ล้น**: C++ `int(obs_data_get_int(...))` ตัดค่า 64 บิตแบบ wrap (2^32+30 → 30); Rust ใช้ saturate test: `out_of_range_numbers_saturate_instead_of_wrapping`
4. **อ่านชื่อ stem แบบฉีก**: C++ `memcpy` ชื่อจาก shared memory โดยไม่ผ่าน seqlock ขณะ Hub กำลังเขียน อาจได้ชื่อขาด ๆ; Rust ใช้ `read_stream_name` (seqlock) ถ้าอ่านไม่ได้ในรอบนั้นก็แสดงแค่ "Stem N"
5. thread ป้อนเสียง panic ไม่ล้ม OBS: ครอบ `catch_unwind` แล้ว log; ถ้าสร้าง thread ไม่ได้ `create` คืน null (C++ ใช้ `std::thread` ที่ throw)

ที่ยังเหมือน C++ โดยตั้งใจ: `StreamConsumer::pull` ครั้งแรกที่ต่อ Hub ได้ alloc 1 ครั้ง (ช่องโหว่ที่บันทึกไว้ใน hs-dsp, R2.4)

## ที่ข้าม / ยังไม่ได้ตรวจ

1. **ไม่ได้เปิด OBS GUI และไม่ได้โหลด scene collection เก่า**: ตรวจผ่านตัวทดสอบ libobs ที่ไม่มี UI เท่านั้น และกับ OBS **33.0.0** ไม่ใช่ 32.2.2 ที่ header อ้างถึง (OBS 32.2.x ยังไม่ได้ลง) การคงชื่อ id / property / hotkey / default ตรวจจากการเทียบกับ `plugin.cpp` และการรันเทียบกับ DLL C++
2. **ปุ่มลัดยังไม่ทำงาน** (R4.2): `remote.rs` เป็น stub; การ port `BusClient` ใช้ `hs_bus::bus::post_remote` ที่มีอยู่แล้ว น่าจะสั้น
3. **Streamlabs Desktop**: ตรรกะสร้าง layout ของ fork มี test (ไบต์ต่อไบต์) แต่ไม่ได้ทดสอบใน Streamlabs จริง (ไม่ได้ติดตั้ง)
4. ไม่ได้ลองกดปุ่ม "Turn Audio Monitoring off" / ปุ่ม Refresh ใน UI จริง; ข้อความไทยของ property ตรวจจาก string เทียบ C++ ไม่ได้ดูภาพ
5. ยังไม่ได้ลิงก์ Linux / macOS (`libobs` จากระบบ) และ CI Linux `cargo build --workspace --release` จะ build cdylib ที่มี symbol ของ libobs ค้าง (undefined) — ปกติ ld ยอมสำหรับ shared library แต่ยังไม่ได้ดู CI รอบแรก
6. R4.4: `dumpbin /dependents hs_obs.dll` = `obs.dll`, `kernel32.dll`, `advapi32.dll`, `ntdll.dll`, `api-ms-win-core-synch-l1-2-0.dll` (C++ ได้ obs.dll + ADVAPI32 + KERNEL32) ต้องดูว่า "ไม่มี DLL อื่น" ของ R4.4 หมายถึงรายการไหน
7. ไม่ได้วัด CPU ของ source เทียบ C++
8. ยังไม่ได้ติดตั้ง/แทน DLL ใน `%ProgramData%\obs-studio\plugins\hearaside-obs\` และไม่แตะตัวติดตั้ง
