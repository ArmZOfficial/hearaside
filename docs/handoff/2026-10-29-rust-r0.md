## C++ bugs fixed in Rust (ledger; ArmZ 2026-10-30: fix every C++ bug in the Rust port)

Fixed (each has a test; golden captures still match):

1. `ring.h` weak-memory hole: no fences around the `writePos` re-check, so on ARM64 a reader may accept
   overwritten samples. Rust: Release fence per chunk + Acquire fence before the re-check (`hs-bus/ring.rs`, loom model).
2. `ringWrite` chunk of `kRingFrames - kGuardFrames`: a host block longer than `kGuardFrames` can be accepted torn.
   Rust publishes every `kGuardFrames`.
3. `ringWrite` / `ringReadAt` with a source/destination shorter than `n`: out-of-bounds read/write. Rust cuts `n`.
4. `Smoother::apply`, `Limiter::process`, `LoudnessMeter::process`, `StreamConsumer::pull` with `n` larger than the
   buffers: out-of-bounds. Rust cuts `n`. `Limiter::process` before `prepare`: null/empty-vector access. Rust no-ops.
5. `StreamConsumer::configure(out_rate = 0)`: null Speex state dereferenced in `pull`. Rust uses 48 kHz and falls back
   to silence when the resampler cannot be built.
6. `StreamConsumer::pull` formats an error string on the audio thread every second (allocation). Rust formats in `status()`.

Fixed during R2.2 (`hs-engine`):

7. `SlotHeader::flags` lost updates: Track `mirror`, Track `process` and the Hub's ViewersViaHub bit all did
   load-merge-store on the same word, so a Solo/Mon toggle or a Hub-set bit could vanish. Rust changes only its own
   bits atomically (`fetch_or/and`, `try_update`). Test `flag_updates_from_different_threads_do_not_overwrite_each_other`.
8. `fedBy == 0` matched an empty friend entry (id 0) while a ViewersViaHub flag was still set: bogus carry. Rust treats
   `fedBy == 0` as nobody.
9. `ahead_blocks` signed overflow (UB) after ~12 h unlocked-and-ahead; Rust saturates.
10. `usedTot + liFrames` unsigned overflow from a huge `fxLatencyBits` read from shared memory; Rust saturates.
11. App Audio source cursors and Track meters survived a reconnect / new claim (stale position, old meter flash); Rust
    resets them.
12. The stem delay read used `cursor - n - delay` unsigned, wrapping in the first block (reads silence); Rust saturates.
13. `numCh == 0` read `io[-1]`; Rust returns early.
14. `TrackPublisher::lastMirror_` was a racy plain struct; Rust keeps it in atomics. `retired_` kept every old bus mapping
    forever (leak per reconnect); Rust releases the mapping in `disconnect`.

Fixed during R2.2b (`hs-engine/src/measure.rs`):

15. History shared as plain floats between the audio thread and the measuring thread (a data race in C++ terms); Rust
    uses relaxed atomic cells in an `Arc<History>`, no lock on the audio side, `prepare` publishes a fresh history.
16. A NaN on the master bus made every correlation score NaN and the C++ accepted the first lag (0 ms, saved as a chain
    latency). Rust treats NaN as "no sound / no match". Test `a_nan_sample_never_becomes_a_measured_latency`.
17. `connect()` to another bus kept the previous bus' history, so the first measurements wrote latencies into the new
    bus' Tracks. Rust starts a fresh history on connect. Test `reconnecting_the_hub_drops_the_old_bus_history`.
18. The history write counter was u32 (wraps after ~4 days at 48 kHz; `HubProcessor` then underflowed
    `historyFrames() - syncFrom_`). Rust uses u64. When porting `HubProcessor`, use `saturating_sub` there too.

19. Speex reallocated its filter on the audio thread at the first `setCorrectionPpm` (den grows from in/out to x k) and
    whenever a same-rate or downsampling ratio passed its previous peak (`FriendReader::pull`, `StreamConsumer::pull`).
    Rust `VarResampler::new` grows the buffers for the largest correction first, then returns to the base ratio (Speex
    only grows, and recomputes the same filter): golden captures unchanged. Not measured with an allocation counter yet
    (C allocations; do it with the Linux `--rt-audit` in R2.4).
