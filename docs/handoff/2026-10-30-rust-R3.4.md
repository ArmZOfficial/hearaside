## สถานะตอบกลับ C++ เทียบ Rust (ส่วนที่ต่าง)

ที่เหมือน C++: POST `/tracks` `/sources` = 404, DELETE/PUT `/tracks` `/sources` = 405 "POST only", method ผิดบน
route ที่มีอยู่ = 405 ตามเดิม ที่ต่าง (ตั้งใจ):

| กรณี | C++ | Rust |
|---|---|---|
| GET / PUT / DELETE path ที่ไม่มี | 405 "POST only" | 404 |
| `/api/v1state`, `/state/x`, segment เกิน | ทำเหมือน route หลัก | 404 |
| `Origin:` ว่าง, `options` ตัวเล็ก | ผ่าน / ไม่ถือเป็น preflight | 403 |
| `Host` / `Authorization` ซ้ำ | ใช้ตัวสุดท้าย | 403 / 401 |
| head เกิน 8 KiB | ปิดเงียบ | 431 |
| `Content-Length` ผิดรูป / ใหญ่เกิน | 0 หรือค่าวน / 413 | 400 / 413 |
| body แบบ chunked | ไม่สนใจ (JSON พัง) | 400 |
| body มีแต่ช่องว่าง | 400 | ถือว่าไม่มี body |
| JSON แปลก (quote เดี่ยว, trailing comma, `1e999`) | JUCE รับบางแบบ | 400 (serde_json) |

ArmZ (30 ต.ค. 2026): ส่วนที่ไม่อยู่ในสัญญาข้อ 3 ปรับให้ดีกว่า C++ ได้เลย จึงคง body ว่าง = ไม่มี body และ JSON แบบเข้มงวดไว้ตามตาราง

## C++ bugs fixed in Rust (ต่อจาก 64 ใน handoff R3.3)

65. client ส่งช้าทีละไบต์ยึดช่องเชื่อมต่อได้นาน (timer รีเซ็ตทุกไบต์): มี deadline รวมของ head และของ body
66. คำขอที่ตอบ 503 ไปแล้วยังค้างคิวและถูกทำทีหลัง (toggle ที่ retry สลับสองครั้ง): ทำเครื่องหมายทิ้งและเอาออกจากคิว
67. คิวงานโตไม่จำกัดเมื่อ message thread ค้าง: แก้ด้วยการเอางานที่ถูกทิ้งออก (`MAX_QUEUE` 16 เป็นรั้วสำรอง)
68. `stop()` ปิด socket ขณะเธรดยังใช้ และปิด listener ไม่ปลุก `accept()` บน Linux: shutdown, join แล้วค่อยปล่อย; listener แบบ poll; รอเธรดเขียน 503 "Hub กำลังปิด" ให้จบได้ถึง 500 ms ก่อน shutdown
69. `Content-Length` อ่านหลวม (`abc` = 0, `12abc` = 12, overflow วน, ซ้ำใช้ตัวท้าย): เข้มงวด 400 / 413
70. body คือทุกอย่างหลัง head ไม่สน `Content-Length`: อ่านตรงตามความยาว
71. `Host` / `Authorization` ซ้ำใช้ตัวสุดท้าย: ปฏิเสธ 403 / 401
72. `Origin:` ว่างผ่าน และ `options` ตัวเล็กไม่ถือเป็น preflight: 403
73. หา `Bearer ` ที่ไหนก็ได้ใน header (`Basic x Bearer <key>` ผ่าน): scheme ต้องเป็นคำแรก
74. head เกิน 8 KiB ถูกปิดเงียบ: ตอบ 431
75. `getIntValue` วน 32 บิต (slot `4294967296` = 0) และแทร็กชื่อ "2" บัง slot 2: slot / index มาก่อน ไม่วน (ชื่อซ้ำยังเลือกตัวแรกเหมือน C++)
76. `viewers_db` ถูกจำกัดที่ +6 ทั้งที่พารามิเตอร์ Track ไปถึง +12, ระดับของ Hub รับ `float(db)` ดิบ (1e300 = inf): จำกัดตามช่วงจาก trait
77. ข้อความ "true" / "false" ถูกตีเป็นการสลับ (`{"on":"false"}` เปิดเสียงที่ปิดอยู่) และตัวเลข int64 ก็สลับ: "true" / "false" ตั้งค่าตามนั้น, ตัวเลข = true ถ้าไม่ใช่ 0, อย่างอื่นสลับเหมือนเดิม (ปุ่ม `{"on":"toggle"}` ยังใช้ได้)
78. path หลวม (`/api/v1state`, segment เกิน, GET path ที่ไม่มีได้ 405): 404
79. เปลี่ยน API key แล้วต้องรอถึง 5 วินาที key เก่ายังใช้ได้: มีผลทันที
80. (ShareServer) ping ที่มาตอนข้อความ WebRTC signaling ยังรอในคิวส่ง ไม่ได้ pong (เพดาน 1024 ไบต์นับ signaling รวมด้วย): นับเฉพาะ pong (`PongBudget`) ทั้ง listener และ friend

คงไว้แบบ C++ (ไม่ใช่การแก้): handler ที่ช้ากว่า 2 วินาทียังทำการเปลี่ยนแปลงหลัง client ได้ 503 ไปแล้ว; ชื่อซ้ำเลือกตัวแรก;
ค่า dB ที่ไม่ใช่ตัวเลขใน track / source ถูกข้าม (200) ส่วน `/stream` `/headphones` ไม่มี `db` = 400 เหมือนเดิม
